# 契約 1 → 2

## 變更

一個主題、一份 HTML PPT、一個獨立資料夾。各主題的根 `index.html` 直接播放，框架與素材都在自己的簡報單位內；框架、品牌、元件、套件與 CLI 記錄集中在單位內的 `agentdeck/`，第一層只留入口、`resources/` 與 `dist/`。只有明確同主體的候選／附件可共存（ADR 0017）。`story`／元件 API 與 `edits.js` 格式不變。

## 逐項改法

1. 盤點既有 `resources/<topic>/index.html`；若入口曾暫時移到 `<topic>/index.html`，也按同樣方式拆分。不同主題各建一個空的 `<位置>/<topic>/`，以 CLI `init` 建立契約 2 單位。不要把多主題工作區整包搬成一個單位，也不要把根目錄的框架檔直接搬進 `agentdeck/` 代替 `init`。契約 0 先依 `0-to-1` 找回既有內容，再進行本拆分；歷史說明保持原樣。
2. 在新單位以 `add` 登記原主題需要的元件。保留 CLI 產生的 `agentdeck/agentdeck.json` 來源、基準雜湊與版本，不複製舊工作區的記錄。將舊主題內容複製到新單位 `resources/<topic>/`，原播放 HTML 複製為根 `index.html`，移除資源副本中的舊入口。人工 `edits.js` 直接複製，核對原始 SHA-256，不重新產生或清空。
3. 把原工作區的客製 `assets/theme/`、已修改元件、自製 `components/` 與所需素材複製到新單位的 `agentdeck/assets/theme/`、`agentdeck/assets/deck/components/`、`agentdeck/components/`。先 `add` 再疊回客製元件，可保留取得時的基準雜湊，讓 `diff` 正確顯示本地修改。套件清單（`agentdeck/vendor.json`）保留需要的版本、網址與 SHA-256；可把原 `vendor/` 快取帶入 `agentdeck/vendor/`，再以 `vendor --check` 驗證。核心本地修改依差異逐項處理，不把舊核心整包蓋回契約 2。原工作區在新單位驗證完成前保留。原本放在第一層的製作腳本與工具移到 `resources/<topic>/`。
4. 換算根入口引用，保留載入順序、query 與 fragment：

   | 契約 1 入口引用 | 新根入口引用 |
   | --- | --- |
   | `../../assets/deck/deck-core.js` | `agentdeck/assets/deck/deck-core.js` |
   | `../../components/example/example.js` | `agentdeck/components/example/example.js` |
   | `../../vendor/three/three.min.js` | `agentdeck/vendor/three/three.min.js` |
   | `story.js` | `resources/<topic>/story.js` |
   | `story.css` | `resources/<topic>/story.css` |
   | `edits.js` | `resources/<topic>/edits.js` |
   | `model-data.js` | `resources/<topic>/model-data.js` |

   若原入口已上移，`../assets/` 改為 `agentdeck/assets/`，`../resources/<topic>/` 改為 `resources/<topic>/`；已在根目錄、以 `assets/`、`vendor/`、`components/` 引用的入口，前面加 `agentdeck/`。把實際依賴持有在新單位內，不引用原工作區或其他單位。
5. 檢查初始 HTML、`previewArt`、`mount` 更新與下載資料中的素材引用。從載入 script 捕捉相對資源前綴：

   ```js
   const resourceDir = document.currentScript.getAttribute('src').replace(/[^/]*$/, '');
   const resource = p => resourceDir + p;
   // art: `<img src="${resource('img/sample.png')}" alt="樣本">`
   // 證據：resource('evidence/result.json')
   ```

   在頂層捕捉，不在事件回呼讀 `currentScript`，不用會轉成絕對 URL 的 `.src`。先釐清資料路徑的基準，再於使用點換算，不盲目替換 JS 字串。CSS `url(...)` 仍相對於 CSS。移除返回舊多主題目錄的 `story.back`；相關內容若需返回主簡報，可用 `resource('../../index.html')`，前提是根主入口存在。
6. 只有確認同一主體的候選／附件才留在同一單位：以 `new <name> --related candidates` 或 `--related attachments` 建立入口，再移入其內容，人工 `edits.js` 保持原始位元組。群組可用其他非保留的有效名稱，入口引用為 `../../agentdeck/assets/`、`../../resources/<name>/`；不同主題不能藉此共存。探索可先建立候選，主入口稍後再定。
7. 新單位用 `pack` 交付整份簡報；`pack <group>/<name>` 選相關內容作首頁是可選操作，僅換算靜態 HTML 引用，須另外檢查 `story.back` 與動態連結，原主入口不保證帶入。不同主題各自打包。更新原製作腳本、宿主 AGENTS 指引與捷徑，指向各單位；不手改 CLI 記錄來假裝已拆分。

## 驗證

- 根入口只載入本單位內的框架與素材；資源資料夾不保留舊播放入口。第一層只剩入口、相關群組、`resources/`、`agentdeck/`、`dist/` 與 `.gitignore`；根目錄不再有 `assets/`、`templates/`、`agentdeck.json`、`vendor.json`、`AGENTDECK.md`。搜尋現行製作腳本的 `pack resources/<topic>`、跨單位 `../assets/` 與舊目錄連結；模板、歷史 ADR、`0-to-1` 及相關入口的合法路徑不算殘留。
- 核對每份 `edits.js` 遷移前後原始 SHA-256；逐頁播放，人工修正與縮圖正常。另存仍放回對應 `resources/<name>/edits.js`。
- 切換案例、方法與參數，換頁再返回；驗證動態圖片、證據連結、下載資料與相關入口。
- `pack` 後解壓到另一位置，根頁直接播放、不含跳轉或 `<base>`；搬移整個單位後重做驗證，確認不依賴原工作區、其他主題或上游。
