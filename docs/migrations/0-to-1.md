# 契約 0 → 1：舊版工作區轉為 `init` 工作區

## 變更

`tools\workspace.cmd` 建立的工作區（`agentdeck.json` 只有 `source`、`commit`、`updated`，視為契約 0）整份複製了框架、全部元件、`examples/`、`tools/`、`docs/`、`AGENTS.md`。契約 1 改為「複製即擁有」：工作區只放核心副本、品牌、用到的元件與簡報，規則改讀 `AGENTDECK.md`，版本由 `agentdeck.json` 的 `contract`、`core`、`components` 記錄（ADR 0016）。簡報的分鏡資料契約、`deck.<name>(key, …)`、`data-*` 標記與 `edits.js` 格式**沒有變**，`story.js`、`edits.js` 不用改。

不要對舊工作區執行 `update core`；以新建工作區再搬移內容的方式轉換，失敗時舊資料夾原封不動。

## 逐項改法

以下以舊工作區 `slides/`、暫存新工作區 `slides-new/` 為例。

1. 建立新工作區：`agentdeck init slides-new`（宿主已有 `AGENTS.md` 時可加 `--agents-hint`）。
2. 搬移下游擁有的內容：
   - `slides/resources/*` → `slides-new/resources/`（含各主題的 `edits.js`、`plan.md`）。
   - `slides/assets/theme/` → 覆蓋 `slides-new/assets/theme/`（品牌）。
   - 舊工作區自行新增的 `docs/` 檔案：需要保留時移到宿主專案的文件位置或 `slides-new/` 下自訂資料夾。
3. 取得用到的元件：搜尋各主題 `index.html` 的 `assets/deck/components/<name>/`，在 `slides-new/` 對每個名稱執行 `agentdeck add <name>`。用到 `vendor/` 套件的元件會自動登記到 `vendor.json`。
4. 舊工作區若改過元件（`assets/deck/components/<name>/` 與當時上游不同）：把差異套回 `slides-new/assets/deck/components/<name>/`，再以 `agentdeck diff <name>` 確認列為「本地已改」。
5. 主題引用 `examples/` 或 `playground/` 的地方：改寫進主題 `story.js`／`story.css`（`agentdeck docs <範例> --code` 讀原始程式）。
6. 替換：確認下方驗證通過後刪除 `slides/`，把 `slides-new/` 改名為 `slides/`。宿主 `AGENTS.md` 若指向舊的 `slides/AGENTS.md`，改指 `slides/AGENTDECK.md`。

## 驗證

- `agentdeck status`：契約 1，核心與各元件「一致」或只有預期的「本地已改」。
- 各主題 `index.html` 中沒有 `examples/`、`playground/`、`tools/` 的引用。
- 逐份雙擊 `resources/<topic>/index.html`：主控台無錯誤、縮圖正常、`edits.js` 的修正仍套用。
- `agentdeck pack resources/<topic>` 成功。
