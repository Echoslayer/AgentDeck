# 需求與資源對齊流程實驗（2026-10-06）

結論：三個獨立 agent 在明確載入目前 skill 的條件下，都依 ADR 0036 的預期完成入口與企劃流程。這是一次小樣本行為驗證，不代表所有 CLI 都會自動觸發 skill，也不代表完整簡報品質或平行加速已通過驗證。此次不需追加流程機制。

## 方法

在 `playground/intake-flow-20261006/` 建立同一份合成專案 Beacon，包含 README、狀態與 CSV。素材有 200 筆合成紀錄：150 通過檢核、30 缺必填、20 格式問題；沒有工時節省或 ROI 證據。三個 fresh subagent 各自讀取本機 `skills/agentdeck/SKILL.md` 與請求，不共享對話或其他案例結果。

評分條件在 `PROTOCOL.md` 預先記錄，未交給受測 agent。為避免向真人發送多份問卷，以檔案保存提問；需要答覆就停，否則完成 plan 後停。A 收到預寫的模擬答覆後續作。各自透過 CLI init/new 建立獨立單位；不製作正式頁面。

## 結果

| 情境 | 實際行為 | 判定 |
| --- | --- | --- |
| A：只說根據專案做簡報、報給老闆，已指定位置 | 先讀三份素材，再一次提出兩組問題：主管要做什麼決定、簡報如何使用。附選項、暫定建議與自由回答方式，沒有重問位置。收到答覆後直接完成 10 分鐘、8 頁企劃，不再要求企劃審批 | 通過 |
| B：對象、目的、時間、形式、資源均已說明 | 無提問，直接完成 10 分鐘、6 頁企劃，記錄 15 分鐘工作上限與本機資源限制 | 通過 |
| C：使用者說方向與形式由 agent 決定、直接做 | 無提問，明列自行採用的假設，完成 5 分鐘、7 頁企劃；未把自行決定方向解讀為外部服務授權 | 通過 |

三組都以素材決定敘事及元件，沒有因為「報給老闆」就強制套商業模板，也沒有套不適用的教學指引。均保留合成資料、尚未上線及效益未實測等限制。plan 都記錄來源、資源範圍與不分工理由；三份短素材缺少值得獨立派工的重工作。

來源三個檔案的 SHA-256 前後一致。三組均建立獨立單位並回報契約 2 一致，停止於內容實作前；產物不是可驗收的完整簡報。

## 觀察與限制

- A 沒有為了湊齊三組問題再問資源授權，而是採用提供素材與本機工具的範圍。這符合「只問會影響決策的缺口」，但本次所有案例都受本機測試邊界限制，尚未測到真正需要外網、付費生成或上傳時的詢問行為。
- A 問卷末尾附上等待答覆的規則說明，文字偏長；該次執行環境要求說明停止依據，不能直接歸因於 AgentDeck 的入口文件。
- B 將三個數值視為完整分組，規劃 split 呈現；A/C 注意到來源未明確保證互斥，採同尺度 bars。這是後續數據語義驗收應留意的差異，不能以入口通過取代內容查核。
- 明確指定了 skill，沒有測試自然語言自動觸發、安裝版 skill 同步或實際選項 UI。
- 測試要求不再派生 subagent，因此只能檢查分工理由，不能證明實際派工率、加速或 token 節省。也未測試複雜專案是否願意製作客製元件。
- 每種情境只有一次，未量測可比較的 token 或工時；不將三組不同任務與 A 的兩回合當成效能對照。
