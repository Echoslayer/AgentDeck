# Site 技術展示：候選元件與互動模式

日期：2026-10-06。實作基準：`1294a3d`。狀態：主題內已驗證，尚未提升為通用元件。

## 問題與方向

使用者要用 site 展示 AgentDeck 的技術上限，同時保留簡單、中等與複雜頁面的節奏。目標是挑選代表性場景，不是逐一展示所有元件，也不是要求每份簡報採用高複雜度實作。

早期空間展示的問題是配色、深度與要表達的關係不清楚；僅讓物件立體化不足以改善理解。這次讓空間操作對應可核對的資料，並保留正面數值視圖。這是設計修正，尚無使用者理解度比較實驗。

## 候選成果與邊界

| 成果 | 本次證據 | 建議歸屬 | 抽取前要補的驗證 |
| --- | --- | --- | --- |

| 原碼、角色與關聯對照 | 三段有路徑、行號、版本的真實原碼摘錄，選檔後同步解說 | 先留作主題模式；未證明需要新的 repo explorer 元件 | 第二個專案對長程式碼、跨檔引用、更新來源快照的需求 |

第二個專案的用途是驗證邊界，不是達到數量後自動抽取。只有資料、操作與清理契約能穩定共用，且不迫使專案遷就展示版型時，才提出元件 API。

## 可回查的實作

- [共用資料、分布圖與頁面連動](../../site/resources/agentdeck/showcase.js)：同一組合成分數由 `count` 計算，頁面共用門檻；選取與視角屬於空間頁狀態。
- [WebGL 視圖](../../site/resources/agentdeck/spatial-webgl.js)：使用已登記的 Three.js；主題內介面為 `mount`、`update`、`dispose`，不構成 registry 公開 API。
- [原碼證據快照](../../site/resources/agentdeck/evidence.js)：固定版本摘錄，並非即時掃描 repo。
- [分鏡與資源紀錄](../../site/resources/agentdeck/plan.md)：雙語敘事、刻意安排的複雜度跨度與驗收紀錄。

## 已觀察結果

- 48 個固定合成、無單位分數：`score >= 60` 為 9 個；`score >= 80` 為 3 個。不是實測準確率或模型輸出。
- 實際點選體素 `X0 Y3 Z2`，分數 24，能切到 Z2 並標出 2D 中相同數值。
- 拆層間距 0／1、鍵盤旋轉、拖曳、縮放與重設通過操作檢查；重設回原視角的畫布截圖一致。
- 三次離頁／返回檢查：離頁無場景 canvas、返回僅一個。程式具有 GPU 資源釋放；未做長時間記憶體壓力測試，不能據此證明完全無洩漏。
- 強制 WebGL 不可用時保留 SVG；仍可切到 Z2，門檻 80 的正面數值顯示保留 1 個。
- 英文與中文各 10 頁；來源 1440×1000、離線包 1440×900、兩者 390px 手機寬度檢查通過，未見水平溢出。封鎖 HTTP(S) 的播放檢查未出現外部請求或 JavaScript 錯誤。
- 離線包約 0.6 MB，包含 Three.js、highlight.js 與匯出依賴。這只是本次包的大小，不是大小優化成效。

本機腳本、結果與截圖位於忽略的 `playground/showcase-20261006/`，不隨 repo 分享；當時使用 `node playground/showcase-20261006/check.cjs` 驗證。本文保存觀察摘要，不把未進 git 的工具當作下游依賴。未量測此次 token、製作時間、GPU 效能、跨裝置相容性或理解度改善。
