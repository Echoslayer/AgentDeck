# 0035. 專案的表達與操作需求優先，以元件重用降低重複實作成本

- 狀態：已接受
- 日期：2026-10-06
- 補充：[0004](0004-component-template-strategy.md)、[0009](0009-components-as-extensions.md)、[0012](0012-template-vs-writing-guide.md)、[0013](0013-component-tiers.md)；保留既有機制，明確其共同目的與取捨

## 背景

AgentDeck 的目的包含降低製作與修改簡報的時間和成本，同時讓 LLM 理解專案，依內容選擇合適的技術呈現與必要互動。現有機制已要求先設計分鏡、依表達關係查找元件，合用就重用，不合用就修改下游副本或在主題內自製；範本只固定框架契約，不固定寫作方式。

這些規則分散在不同決策中，尚未明確說明成本優化的邊界。若把「少用 token」當成最高目標，可能改成先選熟悉模板、再把內容塞進去，或為避免客製而省略重要關係與操作。元件重用本來要節省重複實作，卻可能變成表達的限制。

本次[流程精簡實驗](../studies/token-cost-study-20261006.md)與[文件去重實驗](../studies/token-docs-study-20261006.md)沒有提供足以支持這種交換的證據：文件去重僅觀察到小幅總 token 差異，且受呼叫次數與重試影響，沒有明顯加速。兩組都使用既有元件，不能據此判定元件本身沒有節省成本，也不能推論 PPTX 或 HTML 在所有場景的優劣。

## 決策

1. **需求優先**：先理解專案的目的、素材與證據，決定聽眾需要理解的關係及必要操作，再選擇呈現方式與元件。不為套用固定版型或降低 token 而省略必要內容、能力與驗收。
2. **重用不限制表達**：現有元件能完整支援需求時重用；不完全合用時修改下游副本，或依既有規則在主題內自製。客製以需求為依據，不以新奇為目的，也不為證明專案特色而重寫合適的元件。
3. **保留既有製作機制**：繼續先分鏡、查完整索引、讀選定文件並驗證交付；不因本次成本實驗改成模板優先，或新增省略設計判斷的簡易 workflow。骨架、品牌與使用者明確指定的格式仍可重用，不據此預先限制內容結構。
4. **成本優化守住品質**：優先處理工具失敗、無理由重讀與重複實作等浪費，保留必要的理解、設計、客製及驗收投入。評估改善時同看時間、使用量、內容與功能品質，不以總 token 單獨判定成功；本次文件去重工具保留作實驗，不採用為正式流程。
5. **驗收回到專案**：既有邏輯、文字與播放審查須確認專案需要的關係、證據與操作已被清楚表達；能播放、無溢出或使用了既有元件，都不足以單獨證明適合這個專案。不增加另一套審批流程。

## 後果

- 元件與框架承擔可重用的實作，LLM 保留內容設計與客製責任；成熟元件越多，不代表所有簡報越接近同一版型。
- 接受必要的設計與驗收成本，不保證每份簡報的 token 最少。是否重用或客製依需求適配判斷，不按元件數量或客製比例驗收。
- 後續優化需在相同品質與功能條件下驗證收益；不得把小型靜態案例的結果外推為限制互動或客製的理由。
- 本決策補充目的與判斷依據，不更動元件 API、檔案所有權或資料契約，不需要契約升版或遷移。
