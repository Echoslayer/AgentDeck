# 0039. 文案寫法：目的先行、乾淨素材、只鎖事實、寫稿與查核分開

- 狀態：已接受
- 日期：2026-11-13
- 遵循：[0036](0036-intake-and-resource-scope.md)

## 背景

agent 產出的簡報文字常帶有規格語氣：標題只寫主題名，句子照字數與格式規矩填滿，讀起來不像為這群聽眾寫的。一次對外稿件的派工回溯顯示，第二次能一次通過，差別在四件事：任務說明先講讀者看完要做到什麼，並要求標題寫出目的；工作區只放原始素材與舊稿；結構自由、只守事實底線；寫稿與事實查核由不同步驟負責，不叫寫的一方邊寫邊審。

## 決策

1. 新增寫作指引 `docs/guides/natural-copy.md`，涵蓋上述四點。
2. `AGENTDECK.md`「建立或改版主題」把它設為聽眾可見文字的預設寫法；「平行製作」把文案撰寫與事實查核列為可分派的工作。`templates/blank/plan.md` 分鏡說明加上標題寫法。
3. 方向問題仍走 0036：聽眾看完要做到什麼、素材中的個人是否具名，未確定時併入製作前那一輪詢問，不自行假設。怎麼寫句子、是否分派由 agent 決定。
4. 事實查核只比對引號句與數字並回報，不改句子；不取代 0018 的逐頁邏輯審查。
5. 只新增指引與寫作規則，不遞增契約。

## 後果

- 既有簡報不受影響；改版時才套用。
- 寫稿的 subagent 不拿資料契約，把文案放進 `story.js` 的工作留在主 agent，多一次轉寫。
- 指引是建議（0012）：人指定其他寫法時依人的指定。
- 效果尚未以對照實驗量測；「AI 味」的降低目前只有單次派工的觀察。
