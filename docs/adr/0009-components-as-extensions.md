# 0009. 元件改為按需引用的擴充，範本縮為最小骨架

- 狀態：已接受（範本與頁面模式的位置由 [0012](0012-template-vs-writing-guide.md) 修訂）
- 日期：2026-09-30
- 修訂：[0007](0007-builders-over-markup-rules.md)（產生函式不再集中於單一檔案；範本不再示範全部元件）

## 背景

[0007](0007-builders-over-markup-rules.md) 把八個元件集中在單一產生函式檔，範本也示範了全部元件。元件越多，範本與單一檔案越大，LLM 每次建立主題都得先讀完所有元件，即使大多數用不到；新增元件也要改動所有主題都會載入的共用檔。

LLM 做簡報時真正需要的是：先設計分鏡，再針對某頁的關係找現成元件，找不到就自己做。這跟工具或擴充套件的用法相同：先查目錄，合用才讀說明。

## 決策

1. **核心**：`assets/deck/deck-core.js` 每份簡報都載入，只提供頁型 `deck.cover()`／`deck.end()`、元件註冊器 `deck.define(name, fn, { summary, demo })` 與共用小工具 `deck.util`。
2. **元件**：每個元件一個資料夾 `assets/deck/components/<name>/`，內含 `<name>.js`、`<name>.css`、`README.md`（用途／API／必須保留／範例）。主題在 `index.html` 引用需要的元件，範本不預載任何元件。
3. **目錄**：`components/CATALOG.md` 一行一個元件（表達的關係、用在、不要用在），並列出尚無元件的關係。LLM 只先讀目錄；0007 放在 `AGENTS.md` 的選圖表移入目錄與各元件 README。
4. **契約由核心強制**：每次呼叫 `deck.<name>(key, …)` 時，核心檢查 key 格式、輸出只有單一根元素、根元素 `data-key` 等於 key，違反即報錯。呼叫未引用的元件會報錯並提示引用路徑。元件之間不互相呼叫，組合由呼叫端把一個元件的輸出當成另一個的內容。
5. **展示頁**：`components/index.html` 依註冊順序自動為每個元件產生一頁（取 `summary`、`demo`），供人審核外觀與編輯範圍。
6. **範本**：`templates/visual-story/` 只留封面、一頁自製內容、結尾，以及引用元件的註解位置。預測題與互動頁改為 `README.md`「頁面模式」的程式片段。
7. **升級路徑**：主題先自製元件；同一種元件在第二個主題出現時，LLM 向人提議升級，經同意後依目錄的「新增元件」步驟放入 `components/`（[0004](0004-component-template-strategy.md)）。
8. 修訂 0005「不在執行期警告」的另一處：元件引用了 js 卻漏了 css 時，核心在載入後以 `console.error` 提示。只出現在主控台，不影響播放與縮圖。

## 後果

- 範本與核心保持小；LLM 只讀目錄與實際用到的元件說明，心智負擔與 context 用量都下降。
- 新增元件不動核心與既有元件，互不影響；契約錯誤在呼叫當下就被發現。
- 每個元件多兩行引用，漏引用時由錯誤訊息提示；css 與 js 須成對維護。
- 元件 key 與標記規則不變，既有 `edits.js` 不受影響。
