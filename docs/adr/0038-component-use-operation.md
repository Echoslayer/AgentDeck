# 0038. 以共用 use 操作完成標準根入口的元件接入

- 狀態：已接受
- 日期：2026-10-28
- 遵循：[0016](0016-registry-copy-and-contract-version.md)、[0017](0017-presentation-entry-layout.md)

## 背景

`add` 取得副本並登記套件，但呼叫端還要安排 CSS、套件 JS、元件 JS 的引用與順序，再下載依賴。為 MCP 逐一包裝這些指令，仍會讓每個呼叫端重複知道這些規則。

本機原型以相同三頁內容比較 CLI 手動接入、直接呼叫共用操作與 MCP stdio。三條路徑皆可打包後離線播放；直接呼叫與 MCP 的入口 HTML 相同。證據支持把接入規則集中，但尚未量測獨立 LLM 的成本或成功率。原型保留在被忽略的 `playground/mcp-prototype/`。

## 決策

1. 新增 `agentdeck use <元件…> [--dir <工作區>]`，共用 interface 為 `await useComponents({ dir, names })`，位於 `cli/lib/components.mjs`。完成取得副本、依賴下載及 SHA-256 驗證、CSS／JS 引用排序與去重。回傳入口、接入元件、這次取得項目、套件與入口是否變動；函式不寫 stdout、不啟動 CLI 子行程。
2. 抽出既有 `add` 與 `vendor` 實作供共用；CLI 保留原用法、覆寫選項與訊息。`pack` 仍用同一套下載驗證。MCP server、SDK 與遠端部署不在這輪加入。
3. 第一版只接受工作區範本經 `new` 產生的標準根入口，以及由 `use` 加入的完整引用區塊。以預期 HTML 比對，不嘗試解析任意 HTML；自訂標題、語言、額外 script、相關入口與分頁入口繼續使用手動流程。這是明確的初版支援範圍，後續擴大前須有相應案例與測試。
4. 只累積已接入與這次指定的元件，不把所有已下載元件一起引用。既有副本以取得記錄驗證，保留原版本；修改、刪檔、額外檔案或缺記錄會拒絕，不自動更新、不接受 `--force`。
5. 在修改前預檢名稱、契約、入口、元件與寫入路徑，拒絕符號連結。套件全部驗證後才以暫存檔替換入口；下載期間入口若已改動則保留新內容並報錯。操作不改 `edits.js`、分鏡、品牌與核心。
6. 下載失敗可能留下取得的副本、登記或部分套件，不宣稱整個工作區具有交易性；錯誤說明狀態，問題排除後可以重試。這是本機可信任工作區的製作操作，沒有並行鎖或遠端沙箱。
7. 相容新增，不變更播放契約、不遞增 CONTRACT。測試從 CLI 與相同共用 interface 驗證，下載測試用本地 data URL 與 SHA-256 fixture。

## 後果

- 後續 MCP 可直接呼叫同一個操作，無需複製元件／依賴／入口的規則。
- 標準入口的呼叫端不再負責路徑與載入順序；內容選擇、閱讀元件文件與分鏡仍由作者負責。
- 保守比對會拒絕可正常播放的客製入口，錯誤指引回到 `add` 手動流程，避免改壞作者內容。
- 仍需在真實目標客戶端驗證 MCP 的可達性與 LLM 使用效果，不能從這項 CLI 改善推論 token 節省。
