# 0026. 基本閱讀與個人偏好分層，功能自行提供設定

- 狀態：已接受
- 日期：2026-10-03
- 補充：[0008](0008-decouple-editor-reader.md) 的閱讀器對外介面

## 背景

加入 A／D 翻頁後，設定視窗的 DOM、儲存與按鍵驗證直接散落在閱讀器頂層，並透過編輯器按鈕是否存在判斷要顯示哪些說明。朗讀速度、字幕、講者字級及講稿／註解顯示則已有自己的控制與本機儲存，缺少集中入口。

## 決策

1. 設定介面分成「基本操作」及可展開的「個人客製」。基本操作提供翻頁鍵；客製提供既有的朗讀與講者偏好。品牌、版面、簡報內容及人工 edits 不屬於個人偏好。
2. `reader.js` 的 `createPreferences()` 封裝設定視窗、草稿、驗證、恢復預設、翻頁鍵儲存及按鍵防誤觸。閱讀器只使用 `navigationDelta(event)`；編輯層透過 `storyReader.preferences` 使用 `register(section)`、`isOpen`、`navigationDelta(event)`。原本的 `storyReader.navigationDelta` 保留作為相容入口。
3. `register({title, fields, help})` 的欄位提供 `label`、`default`、`get()`、`set(value)`，以及 `type: 'checkbox' | 'number'`（數字另有 `min`、`max`）或數字 `options`。目前選項用於播放倍率。`set` 回傳 `false` 代表已套用但本機儲存失敗；設定視窗會顯示提醒。這是受信任的框架擴充介面。
4. 功能擁有自己的預設值、儲存鍵與套用行為。編輯層註冊朗讀和講者設定，沿用原有 localStorage 格式；原有按鈕與設定表單共用同一個 setter。設定模組不查詢編輯器 DOM、不掌管語音或講者視窗。
5. 開啟設定時讀取即時值；修改及恢復預設只改草稿，儲存才套用，取消或 Escape 不改偏好。未載入編輯層時不顯示個人客製。瀏覽器拒絕儲存時仍可在本次使用設定。
6. 模組以函式封裝，仍隨既有 `reader.js` 交付；不新增入口 script 或載入順序要求。工作區與頁面資料契約不變，不遞增契約版本。

## 後果

- 新增既有功能的偏好時，修改該功能的設定註冊與 setter，無須修改閱讀器的翻頁或對話框流程。
- 個人偏好仍按瀏覽器來源儲存；不同來源不保證共享，file URL 的儲存行為取決於瀏覽器。
- 字母翻頁鍵可改，方向鍵固定保留；其餘功能快捷鍵目前提供查閱，尚未開放改鍵。
- UI 與快捷鍵的回歸檢查使用真實瀏覽器，透過公開介面及使用者操作驗證，不再擷取函式片段執行。
