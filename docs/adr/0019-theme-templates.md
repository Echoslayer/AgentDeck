# 0019. 簡報以既有模板為主題：init 選主題，PPT 模板經指引轉成主題

- 狀態：已接受
- 日期：2026-10-02

## 背景

有些簡報必須沿用指定的格式模板，例如公司或客戶的 .pptx／.potx。[0010](0010-theme-layer-and-downstream.md) 已把品牌外觀集中在 `assets/theme/`，[0016](0016-registry-copy-and-contract-version.md) 讓 `init` 把它複製進簡報單位，之後歸下游所有。但 `init` 只能帶入上游的預設主題，選別的主題要事後手動覆蓋；也沒有說明如何把 PPT 模板轉成 `theme.css`／`theme.js`，每次都得從頭摸索 OOXML 結構。

## 決策

1. **`init --theme <資料夾>`**：以本機主題資料夾取代預設主題，格式同 `assets/theme/`，至少要有 `theme.css` 與 `theme.js`。來源路徑記在 `agentdeck.json` 的 `theme.source`。未指定時行為不變。
2. **主題庫放在下游**：公司或客戶的主題資料夾由下游自行保存（例如另一個 repo 或共用資料夾），上游不收品牌（[0010](0010-theme-layer-and-downstream.md)）。git 來源先 clone 到本機再指定資料夾，CLI 不處理下載。
3. **PPT 模板經指引轉換，預設只取 logo 與背景**：`docs/guides/theme-from-pptx.md` 寫明從 .pptx 取出 logo 與背景放進主題；配色、字型與母片版面等人提出需求才處理，指引另列對應方式與做不到的部分。原始模板是素材，只讀不改，記在 `plan.md`，不放進簡報單位。
4. **範圍以主題層為限**：轉換只產生色彩、字型、頁首、頁碼、封面與結尾；模板裡的內容版型不新增頁型（頁型屬於框架契約），改用 `story.css` 或既有元件近似。

## 理由

- 主題層與複製擁有的模型已足夠，缺的只是建立時的選擇，所以只加一個選項，不另設模板 registry。
- 多數簡報只需要 logo 與背景就能讓人認出是同一套模板；完整解析母片花費高，卻常常用不到。
- PPT 模板的配色與字型位置固定，需要時 LLM 照指引讀 XML 就能轉換；同一種轉換重複做過幾次之前，寫自動轉換器並不划算。
- 內容版型若一對一變成頁型，等於讓每個品牌擴充框架契約，違背 [0010](0010-theme-layer-and-downstream.md) 的分層。

## 後果

- 已建立的單位要換主題，直接以新的主題資料夾覆蓋 `agentdeck/assets/theme/`，不另設指令；`theme.source` 只是紀錄，不會自動同步。
- 轉換品質取決於 LLM 依指引的判讀，需要在閱讀器內實際看封面、內頁與結尾再交付。
- 若之後同一種模板轉換反覆出現，再考慮 `agentdeck theme import` 之類的轉換器。
