# 0024. 講者動作隨朗讀執行：record 步驟加 at，新增 arrow、box、clear 與 cues

- 狀態：已接受
- 日期：2026-10-02

## 背景

[0022](0022-speech-read-aloud.md) 讓簡報能念口語稿並自動翻頁，但講者動作（`instruction` 裡的「指左邊」「切到 B」）仍要人在台上做，無人播放時畫面不會動。[0021](0021-pptx-export.md) 的 `record` 已有一套可重播的操作步驟（`wait`、`click`、`set`、`drag`），只用於匯出錄影，與朗讀沒有時間關係。

同步要面對兩件事：一是外部音檔與語速。音檔播放位置 `currentTime` 以音檔本身的秒數計算，不受 `playbackRate` 影響；內建語音沒有秒數，只知道念到第幾句。二是複雜度。逐字同步、關鍵影格、緩動與時間軸編輯器會讓框架變成影片剪輯工具。

## 決策

1. **沿用 `record`，步驟可加 `at`**：`at` 是口語稿的第幾句（1 起算，斷句規則同字幕：句末標點 `。！？!?；;` 或 `<br>`）。朗讀進到該句時執行該步，之後沒有 `at` 的步驟屬於同一組，依序執行；`wait` 依語速縮短。前一組還沒做完時，下一組排在後面。`record` 裡沒有任何 `at` 時只給匯出錄影，播放不執行，既有簡報不受影響。
2. **新增三種標註步驟**：`arrow`（選擇器，`from` 為 `left`／`right`／`top`／`bottom`，預設 `left`）、`box`（紅框），都可加 `text` 顯示短標籤；`clear: true` 移除目前的標註。標註疊在畫面上、不擋點擊，換頁、停止或重新播放時移除，念完時保留到換頁。
3. **操作以合成事件執行**：`click` 呼叫元素的 `click()`，`set` 設值並觸發 `input`、`change`，`drag` 送出指標事件；三者都在操作點顯示點擊光圈。合成指標事件沒有真的指標，`setPointerCapture` 會丟例外，拖曳期間暫時略過。
4. **選填欄位 `cues`**：音檔中每句口語稿的起始秒數（由小到大），字幕與 `at` 照秒數對齊；句數不符時載入時警告。沒有 `cues` 時退回 0022 的估算（依播放進度按句子字數比例）。內建語音以句子開始事件對齊，不需要 `cues`。時間點的產生（語音服務的時間資訊、Whisper 對齊、人工標記）不在框架內。
5. **全部播放等動作做完才翻頁**：本頁最後一組動作完成後，才計時翻到下一頁。
6. **匯出共用同一份步驟**：`agentdeck export` 照順序執行所有步驟並忽略 `at`；`arrow`／`box`／`clear` 交給簡報自己的 `deck-editor.js`（`window.deckActions`）畫，標註後停 400 毫秒讓影片看得清楚。錄影只裁 `.stage`，標註要落在 `.stage` 內。
7. 實作在 `deck-editor.js` 與 `cli/lib/export.mjs`，不新增套件；相容新增，契約版本不遞增。

## 理由

- 一份步驟同時給播放與匯出，作者只維護一套；`at` 只是附加的時間錨點。
- 以句子為錨點，內建語音與音檔共用同一套寫法，語速改變不必重寫；需要精準時再加 `cues`。
- 倍速不影響對齊：音檔以 `currentTime`（音檔秒數）判斷，內建語音以句子事件判斷，只有組內 `wait` 需要依語速縮放。
- 以 `requestAnimationFrame` 讀播放位置，避免 `timeupdate` 約 250 毫秒的間隔造成延遲。

## 後果

- 不做逐字同步、緩動、關鍵影格與時間軸編輯器；需要這些時改用影片。
- 動作改變的元件狀態不會在重播時還原（`mount` 的狀態依頁保存）。可重播的寫法優先用 `set` 指定值，少用切換型的 `click`。
- 沒有 `cues` 的音檔，動作與字幕一樣是估算，可能早或晚一兩句。
- 合成事件只觸發元件自己的事件處理；依賴瀏覽器預設行為（如原生拖放、捲動）的操作不保證有效，匯出錄影（Playwright 真實滑鼠）則不受此限。
- 標註顏色固定為紅色，與主題無關，避免和品牌色混淆。
