# 0034. 相關簡報預設各自成單位，明顯耦合時才合為相關入口並只經單一共用資料檔耦合

- 狀態：已接受
- 日期：2026-10-05
- 修訂：[0017](0017-presentation-entry-layout.md) 決策 3 的「同一主體」判準

## 背景

同一套系統常要做好幾份簡報，例如「系統實際怎麼運作」的事實冊與「還有哪些 bug」的問題冊。0017 只說「明確屬於同一主體」的候選與附件可共存，沒有說題材相關但各自成冊的簡報該怎麼放。

實作時先把兩冊各自 `init`，事實冊裡的「→ 另冊 B4」只能是文字，點不過去；bug 的優先序、標題與修正狀態在兩冊各寫一次，修好一項要改兩處，容易漏改。量測後分開的成本不在資源或 token：每份框架副本約 1.4 MB、zip 約 430 KB，修改時讀的內容檔大小相同；差別在更新時要同步兩份框架與兩份資料。

反方向也有風險：只因題材相近就合併，兩份不相干的簡報會共用框架版本與交付範圍，失去 0017 的獨立搬移與獨立更新。

## 決策

1. **預設分開**：題材相關的簡報仍各自 `init`。
2. **明顯耦合才合併**：符合以下條件時，放進同一單位，主入口之外的冊以 `new <name> --related <group>` 建立：頁面互相引用，或要同步會變動的資料（例如問題清單與修正狀態），且刻意一起交付。群組名表達關係（如 `issues`），不必是 `attachments`：附件是主簡報的補充，耦合的另一冊可以獨立閱讀與決策。
3. **耦合只經過一個共用資料檔**：放在主入口的 `resources/<主題>/`，兩個入口都在 `story.js` 之前引用。共用檔以自己的 `document.currentScript.getAttribute('src')` 推算單位根目錄，產生跨入口連結。其餘內容各冊自己持有，不互相讀對方的 `story.js`。
4. **跨入口連結**：以相對路徑加 `#頁面 id` 開到指定頁。閱讀器翻頁時以 `replaceState` 更新網址，所以瀏覽器的上一頁會回到點擊時所在的頁；不另做返回參數。`story.back` 仍只回主入口。
5. 匯出成圖片後連結失效：連結文字本身要能獨立閱讀（寫出目標冊與編號）。

## 後果

- 耦合的兩冊共用一份框架，`update core`、`add`、`pack` 都只做一次；修正狀態改一處，兩冊同步。
- 沒有耦合的相關簡報保持獨立，代價是框架副本重複（每份約 1.4 MB）。
- 共用檔是兩冊之間唯一的依賴；改它的欄位時，兩個入口都要播放驗證。
- 只選相關入口作交付首頁（`pack <入口資料夾>`）時，連回主入口的連結要另外驗證，與 0017 決策 5 相同。
- 不改閱讀器、CLI 或契約版本。
