# 0003. 現場隱藏作為元件錯誤的容錯手段

- 狀態：已接受（畫布判定由 [0008](0008-decouple-editor-reader.md) 修訂為 `data-canvas`）
- 日期：2026-09-30

## 背景

元件由 LLM 實作，可能到現場才發現顯示錯誤或互動故障。現場無法改程式，而依 [0002](0002-content-layers.md)，元件內容本來就鎖定。沒有退路的話，一個壞掉的元件就會拖垮整頁簡報。

## 決策

- **不能改，至少要能藏**：編輯模式下，每個可隱藏的元件右上角有 👁，點一下切換顯示。隱藏狀態寫入 `edits.js`。
- 預設可隱藏範圍：
  - 頁面欄位 `section`／`title`／`lead`／`point`／`detail`。
  - 舞台 `.stage` 的第一層元件。
  - 畫布版面（`.deck-cover`、`.deck-end`）則以畫布內的元件為單位，例如 logo、標題、說明。
  - 鎖定元件（包括 logo）也能隱藏。
- 更細的粒度（例如只隱藏三張卡片中的一張）由 LLM 在子元件上加 `data-hide`（並加 `data-key`）開放。
- 隱藏的元件在編輯模式顯示為半透明加紅框；播放時和縮圖中都不顯示。
- 隱藏不附原因。事後由人告知 LLM 哪些是錯誤、需要修。
- 編輯列本身也可以隱藏（✕），按 `E` 重新顯示，避免正式播放時干擾畫面。
- **對 LLM 的設計要求**：每個獨立元件在 `art` 中應是單一第一層元素（或畫布內的單一元素），這樣出錯時才能單獨隱藏，不會連帶藏掉其他內容。

## 後果

- 簡報不會因為單一元件出錯而無法進行。
- 隱藏不等於修復：錯誤仍要回到 LLM 層修正。`edits.js` 裡的隱藏項目沒有原因，要由人補充說明。
- 隱藏粒度取決於 LLM 是否依規範拆分元件和加標記。
- 隱藏狀態以 key 記錄；key 穩定性見 [0005](0005-data-key-attribute-model.md)。
