# 0020. 每頁的口頭說明與註解：作者寫進 story.js，人寫進 edits.js

- 狀態：已接受
- 日期：2026-10-02

## 背景

LLM 寫分鏡時，清楚每一頁的意圖、鋪陳和該怎麼講，但這些資訊沒有地方留下，講者拿到簡報只看得到畫面。審閱的人對某頁有意見，也只能寫在聊天紀錄或其他文件；下一輪修改時，LLM 從簡報單位內讀不到。曾在 playground 試作三種介面：翻頁列上方的窗格、右側欄、另開的簡報者視窗。窗格會和投影片搶畫面高度，最後選用右側欄與簡報者視窗。

## 決策

1. **講稿分兩個欄位**：都是頁面資料的可選字串（HTML），由作者（LLM）寫在 `story.js`，`deck.cover()`、`deck.end()` 也接受。
   - `instruction`（講者動作）：怎麼開口、指哪裡、操作什麼、怎麼接下一頁，用口語寫。實作時每頁都寫。
   - `explain`（補充解釋）：畫面簡化或省略了什麼，聽眾追問時的原因與答法，例如模型為何把某個數字判錯。這部分要回到素材與實測資料查證，在整份簡報完成後的講稿二次迭代才寫，只寫需要的頁。
2. **註解 `comments`**：人對各頁留的純文字註解，存在 `edits.js` 的 `comments[頁面 id]`，每則包含 `text` 與本地時間 `at`，一頁可以有多則。註解沿用頁首「另存」，和其他人工修改寫進同一個檔案。
3. **右側「講稿」「註解」兩個分頁**：講稿與註解是兩個功能，各有一個標籤，與左側索引對稱且行為相同：滑鼠移上去暫開、移開收起，點標籤釘選（N、C 鍵也可以），一次只開一個。「講稿」顯示本頁的講者動作與補充解釋；「註解」可新增或刪除註解，索引縮圖標出各頁註解數。正在輸入註解時不會因滑鼠移開而收起。放大播放或隱藏編輯列時不顯示。
4. **簡報者視窗**：頁首「🎤 講者」另開視窗，顯示頁碼、計時、講稿、下一頁標題、翻頁按鈕與註解，和主視窗同步翻頁。講稿與註解可個別開關，字級可用 A−／A＋ 調整，存在講者本機；補充解釋以較小字級顯示在講者動作下方。
5. 兩者都放在 `deck-editor.js`，不新增檔案或載入順序，屬於相容新增，契約版本不遞增。

## 理由

- 口頭說明是作者產出，跟著分鏡改版；註解是人工輸入，由人擁有。沿用 `story.js` 歸作者、`edits.js` 歸人的分工（[0002](0002-content-layers.md)），LLM 不必修改 `edits.js` 就能讀到註解。
- 右側欄平常收合，不占投影畫面；雙螢幕上台時由簡報者視窗提供講稿，觀眾畫面保持乾淨。
- 動作和解釋的讀法不同：動作要在台上一眼看完，解釋是備查。分開後，簡報者視窗可以把動作放大、解釋縮小。解釋需要整份的脈絡和查證，第一輪就寫容易寫成沒有根據的猜測，所以留到二次迭代。
- 編輯層已經擁有 `edits.js` 與「另存」，把註解放在同一層，不需要再公開一套給外掛使用的介面。

## 後果

- `edits.js` 多了 `comments` 欄位；舊檔沒有這個欄位時照常運作。
- `pack` 會帶入註解，收到打包檔的人打開右側欄就看得到。交付給外部前，由人決定是否先清掉註解。
- 註解以整頁為單位，不能指定頁面上的某個元件；需要時再以 `data-key` 對應。
- 簡報者視窗靠 `window.open` 開啟，瀏覽器擋下彈出視窗時會提示，需要人允許。
