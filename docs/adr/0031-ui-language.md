# 0031. 閱讀器與編輯層的介面語言跟隨 `<html lang>`

- 狀態：已接受
- 日期：2026-10-05

## 背景

閱讀器、編輯層與分享匯出的介面文字（翻頁、索引、設定、標示工具、編輯列、講稿與註解、匯出對話框）全部寫死為繁體中文。英文簡報的內容是英文，按鈕卻是「上一步」「✎ 編輯」，無法對外發表；專案網站也需要英文主入口與中文版本（[0032](0032-pages-site-unit.md)）。

## 決策

1. **語言來源**：介面語言取自入口的 `<html lang>`。以 `zh` 開頭或未設定時為中文，其餘一律為英文。簡報不另設欄位，作者只改入口的 `lang`。
2. **寫法**：`reader.js`、`deck-editor.js`、`export.js` 各自定義 `uiText(zh, en)`，在用到文字的位置成對寫出中英文，不建立字典檔或語言包。翻譯緊貼原文，改文字時一起改。
3. **入口 HTML 的靜態文字**（索引「投影片」、「釘選」、翻頁列的 `aria-label`、放大按鈕的提示）仍以中文寫在範本；英文介面由 `reader.js` 在載入時替換，範本不變。
4. **核心頁型**：`deck.cover()`／`deck.end()` 的預設 `section` 依同一規則為「封面／結尾」或 Cover／End。
5. **不翻譯**：開發者看到的錯誤（契約檢查、`throw`、主控台訊息）、`edits.js` 檔頭註解、元件展示頁的範例資料，以及元件內建的預設提示文字。元件的預設文字可由呼叫端以參數覆寫（例如 `stack3d` 的 `hint`）。
6. 只新增行為，資料格式與既有中文簡報的外觀不變，不遞增契約。

## 後果

- 英文簡報只要把入口改成 `<html lang="en">`，介面就是英文；既有 `lang="zh-Hant"` 的簡報不受影響。朗讀原本就依 `<html lang>` 挑語音，介面與語音一致。
- 只支援中英兩種語言。要加第三種語言時，`uiText` 改為依語言查表，並同步所有呼叫處。
- 元件內建的中文提示（例如部分特殊元件的操作提示）仍需呼叫端覆寫；要全面英文化時另行處理元件。
