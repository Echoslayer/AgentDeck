# 0036. 製作前由 agent 一次對齊方向與資源，提供建議答案並自主安排實作

- 狀態：已接受
- 日期：2026-10-06
- 補充：[0018](0018-plan-to-build-and-teaching-attachments.md) 的企劃前需求對齊、[0023](0023-parallel-pages-and-join.md) 的分工判斷；遵循 [0035](0035-project-needs-before-template-cost.md)

## 背景

使用者通常以自然語言提供專案路徑與用途，例如「根據這個專案做一份 AgentDeck，報給老闆」，不會指定寫作指引或 subagent 分工。「報給老闆」只說明聽眾，尚未區分報進度、提出風險或爭取資源；直接製作可能造成返工。反過來，空白問卷與逐題訪談又把判斷負擔交回使用者。

素材可能來自 repo、文件、數據、既有簡報或品牌資源；能讀指定資料不代表可對外傳送、付費或改動來源。已有平行分頁與 join 機制，但只寫「可分工」，或只看頁數與是否互動，不能確保 agent 在合適的工作上使用它。

## 決策

1. **自然語言入口由 agent 處理**：先在已授權範圍內初讀素材，再一次詢問尚未確定且影響方向的問題，優先合併為至多三個主題：對象與目的、範圍與使用方式、資源與限制。工作區位置疑問一併處理；不要求使用者指定指引名稱或 CLI 命令。
2. **問題附建議答案**：每題二到三個具體選項與簡短影響，根據已有資訊推薦，資訊不足時標示假設。允許自由回答與「照建議做」；預選或未回覆不算確認。需要回答的部分等待，其他已授權準備可繼續。只在出現新關鍵缺口時追問。
3. **按實際需求對齊資源**：可用「提供的資源與本機工具為主／允許公開查證與補充／另允許實驗或生成素材」協助討論，記錄具體資料、服務、對外傳送與時間／費用邊界，不建立固定權限套餐。已有授權沿用；未涵蓋的付費、上傳、發布、改來源或新增套件不能自行推定。
4. **明確或授權自行決定就繼續**：不為每次改稿重問完整清單。使用者說「你決定」時記錄方向假設並在既有資源範圍內工作；方向清楚後仍依0018先寫plan直接實作，只有人要求才先審企劃。需求釐清與企劃審批是兩件事。
5. **agent 自主選指引與分工**：按目的和素材選用既有catalog/docs，不把聽眾標籤當成固定版型。企劃時評估可獨立交付的重工作；宿主支援且允許時分派適合的任務，主agent同步處理其他工作，不適合則簡記理由。subagent繼承相同資源／預算邊界，跨CLI或外部服務不因平行授權而自動獲准。
6. **沿用既有載體**：執行規則放AGENTDECK.md，skill只銜接入口，plan記錄方向、假設、素材與分工。不新增CLI問卷、插件系統、固定頁型或另一套workflow。

## 後果

- 使用者選擇影響成品的方向與資源邊界，實作細節由agent負責；可以減少方向錯誤的返工，但不承諾已證明省時。
- 重要資訊缺失時會有一輪等待；已明確的需求與授權不被新的問卷打斷。新增外部行動仍依實際授權判斷。
- 重靜態圖解與多來源分析也納入分工候選；不強制每份簡報開subagent。實際加速仍需衡量整合、等待與修正後的總時間。
- 這是作者工作方式與企劃提示的更新，不改資料契約、播放API或檔案佈局，不需契約升版；既有下游規則副本需依正常更新流程取得。
