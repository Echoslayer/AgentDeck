# 0037. 術語註：畫面以 `<dfn>` 標記，定義集中在 `story.glossary`，讀者點開才看

- 狀態：已接受
- 日期：2026-10-13

## 背景

主簡報只留案例、結果與產物（ADR 0018），原理放附件，講者的補充寫在講稿（ADR 0020）。但簡報常在沒有講者時被自己讀：讀者不會打開右側講稿，附件又太遠，遇到一個不懂的術語就卡住。

參考 ISO 24495-1 淺白語言的「找得到」原則：主文保持精簡，讀者需要時能就地查到解釋。畫面上不能多放文字；只靠 hover 在觸控裝置與投影時無效。

## 決策

1. **標記在畫面文字**：作者以 `<dfn>詞</dfn>` 標出可查的詞，顯示文字與詞條不同時加 `data-term`。不自動比對字串，標哪些詞由作者決定。
2. **定義集中在 `story.glossary`**：`{ 詞: '一句定義' }`，載入時檢查型別；頁面用到但缺定義的詞在主控台報錯。
3. **閱讀器呈現**：`reader.js` 在每次渲染後為 `#page dfn` 補上鍵盤可達性；點擊、Enter／空白鍵開卡片，滑鼠裝置另支援 hover。卡片用原生 `popover`，點外面與 Esc 關閉。編輯模式不攔截點擊；點術語不翻頁。放大投影時隱去底線，仍可點開。不加套件，不做成元件。
4. **匯出**：`agentdeck export` 把該頁用到的術語寫進 PPT 備忘稿的「【術語】」段；頁首「匯出」的圖片版不含術語註，與講稿相同。
5. **寫作邊界**：一頁至多 2–3 個、只標首次出現、定義一句話；超過一句的放附件或 `explain`。規則寫在 `AGENTDECK.md`。
6. **由 agent 判斷何時使用**：人不會指名要這個功能。agent 依 `plan.md` 的聽眾與場合判斷：聽眾不懂、但不是主旨、一句話講得清的詞才用；是主旨就寫在畫面上，講不清就放附件。會後自行閱讀、線上分享、打包寄出時照標；只在現場投影時優先寫進 `instruction`。觸發點有二：`plan.md`「對象與目的」的「術語」列，以及交付前逐頁審查時以聽眾身分讀每頁。
7. 只新增可選欄位與標記，不遞增契約。

## 後果

- 既有簡報不受影響；用到 `<dfn>` 卻沒有 `glossary` 的舊內容會在主控台報錯，補定義或改成一般文字。
- 術語註成為塞文字的出口時會稀釋主線；靠第 5 點的寫作規則與交付前的逐頁審查把關。
- 卡片位置以 JS 計算；CSS anchor positioning 普及後可改用原生定位。
- 研究原型在 `playground/glossary-demo/`（不進 git）。
