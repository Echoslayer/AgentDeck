# 0015. 互動組合範例隨專案交付，與正式元件分開

- 狀態：已接受
- 日期：2026-10-01
- 補充：0009（元件查找）、0012（寫作指引）、0014（可攜工作區）

## 背景

XAI 試驗證實一頁可以承載完整的互動實驗，前後頁說明範圍與解讀。門檻、投票、資料語意與結論仍與主題相關，直接抽成通用元件會過早增加設定。既有 playground 不進 git，不能承載需要隨專案交付的範例與實作經驗。

## 決策

1. `assets/deck/components/` 保持正式元件：透過穩定 API 傳入資料直接使用。
2. 新增 `examples/` 並進 git，存放可離線試玩、可依主題改寫的互動組合範例。每份附說明、必要的追加文件、資料快照與可執行檢查；不承諾穩定 API。
3. `playground/` 保持本機試驗、不進 git。選定的成果整理到 examples；出現跨主題的相同需求後再提議抽成元件。
4. 查找分兩階段：CATALOG 與 examples 目錄提供表示關係與選用條件；實作前讀選定元件或範例自己的 README 與追加說明。現成元件與參考實作在展示入口分區標示。
5. 主題從範例摘用並改寫程式與資料到 `resources/<topic>/`；不得執行期引用 examples 或 playground。範例可互相引用，因此範例交付以整份 examples 打包。
6. workspace 建立與更新包含 examples，視為上游維護、整份取代的參考資源。下游自有內容放 resources。pack 拒絕正式主題 HTML 直接引用 examples，其他動態引用仍須作者檢查。
7. 範例按表示關係命名並使用最小人工資料：解析度比較、門檻與共識、加權評分。每份分開計算、示範資料與畫面更新，文件說明適用條件及改寫位置；領域特定的 XAI 試驗留在不進 git 的 playground，不另交付案例庫。LLM 先讀選用摘要，選定後才讀該範例文件與必要程式，避免為查找表示方式載入全部實作。

## 後果

不新增閱讀器或互動框架，沿用頁面資料契約與生命週期。LLM 可以重用組合方式而不必先設計通用 API。範例快照增加少量 repo 體積，但 clone 與工作區不需要原始 XAI 專案即可試玩。
