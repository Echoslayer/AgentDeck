# 0002. 內容分層：story.js（LLM）與 edits.js（人工）

- 狀態：已接受（載入順序由 [0007](0007-builders-over-markup-rules.md) 補充產生函式，[0009](0009-components-as-extensions.md) 改為 `deck-core.js` 與按需引用的元件）
- 日期：2026-09-30

## 背景

LLM 負責產出與改版；現場小修的人可能是簡報者（只會用瀏覽器），也可能是工程師。若兩者都直接改 `story.js`，LLM 下次改版時會覆蓋人工修正，人也無法分辨哪些是自己改的。

瀏覽器在 `file://` 下無法直接寫檔。

## 決策

- **`story.js`（LLM 層）**：內容、版面、元件、互動。由 LLM 維護；工程師直接改 `story.js` 視同 LLM 層改版。
- **`edits.js`（人工層）**：只存現場修正，包括文字、位置與隱藏狀態。載入順序為 `story.js` → `edits.js` → `deck-editor.js` → `reader.js`，在渲染前覆蓋到分鏡資料上，所以縮圖與索引也看得到。
- 現場修正一律透過播放頁的「✎ 編輯」模式進行，實作在 `assets/deck/deck-editor.js`：
  - 可編輯：頁首主題名稱；各頁 `section`／`title`／`lead`／`point`／`detail`；作者標記可編輯的文字；作者標記可拖曳的位置（以舞台寬度 `cqw` 保存）。
  - 允許粗體、斜體、底線、換行、清單。貼上一律轉純文字；保存前移除所有屬性與非格式標籤。
  - 未標記的元件（logo、底圖、顯示元件、互動）內容一律鎖定。
- **預設不保存**：重新整理即還原。按「另存」（Ctrl+S）將全部修改輸出為 `edits.js`，由人放回主題資料夾。
- **回流由人決定**：何時把 `edits.js` 吸收回 `story.js`，由人指示。LLM 不會自行合併或清空 `edits.js`。

## 後果

- 人工修正與 LLM 產出互不覆蓋，而且可以分開檢視。
- `edits.js` 以 key 對應元素。LLM 改版若變動 key 或元件順序，修正可能對不上或套到錯的元件，因此另立 [0005](0005-data-key-attribute-model.md) 統一穩定識別。
- 另存要人手動放回檔案，多一步操作；這換來的是零依賴，而且不會誤存。
- 內容頁是流式排版，拖曳只建議用在封面、結尾這類絕對定位的版面。
