# 語音與講者動作指引（建議，進階）

適合內容已定稿、人要求朗讀、無人播放或畫面跟著口語稿動的簡報。這是寫作建議，欄位格式與規則以 `AGENTDECK.md`「進階欄位」「進階內容」為準（ADR 0022、0024、0025）；本指引只補充怎麼寫得穩。不要在第一輪製作時套用。

## 先確認可以開始

- 內容已經人播放確認，畫面、版面與 `data-key` 不再大改。句數或元件位置一變，`at`、`cues` 與選擇器都要重寫。
- 每頁已有 `instruction`。動作從 `instruction` 挑，不另外發明。
- 人說清楚要的是哪一種：只要朗讀（寫 `speech`）、要畫面跟著動（再寫帶 `at` 的 `record`）、要 PPT（見下方「匯出」）。沒要求的不做。

## 工作順序

1. **口語稿定稿**：照 `instruction` 的順序寫 `speech`，一句講一件事。要搭配動作的那句，讓它單獨成句。
2. **編句號**：依斷句規則（句末 `。！？!?；;` 或 `<br>`）數出每句是第幾句，在 `plan.md` 該頁旁記下「句 2：指出 A」。之後改口語稿時，先對照這張表改 `at`。
3. **挑動作**：每句最多一個重點動作，選法見下一節。
4. **寫 `record`**：帶 `at` 的步驟開始一組，其後的 `wait`、標註或操作屬於同一組。一組的總長度要比該句念完的時間短，不然下一組會排隊、越來越晚。
5. **對時間**：有音檔且要求精準時才寫 `cues`；否則依播放進度估算，通常就夠用。
6. **播放檢查**：按 R 念本頁、P 逐頁播放，切換語速再看一次，確認動作落在對的句子、標註沒有蓋住正在講的內容。

## 選哪種動作

| 講者要做的事 | 用 | 注意 |
| --- | --- | --- |
| 「看這裡」指出一個區塊或數值 | `box` | 指向帶 `data-key` 的小區塊或行內元素，不框整段 `<p>` |
| 「從這邊看過去」指向位置或方向 | `arrow` | `from` 選空白較多的一側，箭頭要留在 `.stage` 內 |
| 換一個重點 | `clear` 後再標下一個 | 相鄰的標註不帶 `text`，或分開在不同句 |
| 切換樣本、改參數、看結果變化 | `set`（優先）或 `click` | `set` 指定值可重播；切換型 `click` 重播時可能切回去 |
| 旋轉、拖曳畫布 | `drag` | 只用在畫布類元件 |
| 講到某個詞才畫重點 | `mark` 設 `auto: false`，`click` `[data-mark="n"]` | 一句一個標記；再點不會收回 |
| 一句執行一個終端機指令 | `terminal` 設 `auto: false`，`click` `.deck-terminal-next` | 依序前進；重念前先翻頁或按「從頭」 |
| 講到「放開」「完成」才開始動畫 | `physics`／`lottie` 設 `auto: false`，`click` 開始按鈕或 `.deck-fallback` | 每次都從頭，重播安全 |
| 聚焦網路圖的一個節點 | `network` 的聚焦選單，`set` 節點 id（`''` 為全部） | 不要 `click` 畫布 |
| 指出 sankey 節點或 treemap 方塊 | `box`／`arrow` 指向 `[data-node="名稱"]` | 名稱要與資料完全相同 |
| 宣布結果時噴彩帶 | `celebrate` 包住的按鈕，`click` | 只用一次 |
| 下載、送出、開新頁 | 不寫進有 `at` 的 `record` | 改用標註指出位置，由講者手動操作 |

會自己播放的元件（`terminal`、`lottie`、`physics`、`mark`）在翻頁時就開始，朗讀還沒講到就播完了；要跟著句子動時一律設 `auto: false`，再用上表的動作觸發。各元件的寫法見其 README 的「隨朗讀」。

能用標註表達的就不要操作元件。標註只疊在畫面上，不改元件狀態，重播與換頁都不會留下副作用。

## 常見錯誤

- **同一組裡「框 → 清除 → 框」沒有間隔**：三步會在同一瞬間做完，第一個框看不到。中間加 `wait`，或把後一個框放到下一句。
- **口語稿改了，`at` 沒跟著改**：動作會錯開一句，看起來像講者指錯地方。改稿後重新數句子。
- **標註標籤蓋住內容**：`text` 畫在框的左上方。框靠近頁面頂端或旁邊有文字時，省略 `text`，或改用箭頭。
- **一組太長**：多個 `wait` 加總超過該句長度，後面的動作會整串延後。拆到後面的句子，或縮短 `wait`。
- **選擇器依賴順序**：用 `:nth-child` 等位置選擇器，版面一調就會指錯。優先用 `data-key`。

## 外部音訊與語速

- `audio` 是人提供或預先產生的錄音；`speech` 仍寫成逐字稿，句數要和錄音一致，`at` 與 `cues` 才對得上。
- `cues` 的秒數從語音服務的時間資訊、對齊工具或人工標記取得，一句一個。沒有 `cues` 時依播放進度估算，句長差很多的稿子可能偏一點。
- 語速切換時，`wait` 會跟著縮短；不要用很長的 `wait` 來「等講者講完」，那是 `at` 的工作。

## 匯出 PPT 時會怎麼轉

同一份 `record` 也用於匯出（ADR 0021、0024、0025）：

- 只有 `box`、`arrow`、`clear`、`wait` 的頁：截圖加上 PPT 原生紅框與箭頭，每按一下依序出現；不需要 ffmpeg，標註在 PowerPoint 裡也能改。
- 含 `click`、`set`、`drag` 的頁：照順序錄成影片，忽略 `at`，不帶朗讀時間。

所以設計動作時，只是指出重點的頁用標註就好，PPT 端的效果會比較好。但不要為了匯出去改寫已經確認過的播放步驟，也不要向人保證 PPT 會保留朗讀同步。

## 最小驗收

1. 每頁 `speech` 的句數與 `plan.md` 的句號表一致；有 `audio` 時與錄音一致，有 `cues` 時秒數個數相同。
2. 以 R 與 P 播放，至少兩種語速下動作落在對的句子；換頁、停止、重播後沒有殘留的標註或改變的狀態。
3. 有 `at` 的 `record` 不含下載、送出等副作用操作。
4. 要 PPT 時先跑 `agentdeck export --check`，確認選擇器都找得到；輸出後在 PowerPoint 放映模式按一次，確認標註依序出現。

完成時分開回報播放檢查與匯出檢查。
