# 更新既有簡報與元件數據指引（建議）

適合替換實驗結果、更新指標或新增資料批次。目的是讓資料、呈現與解讀一致，保留專案需要的表達及人工修改；不規定頁序、版型或元件。資料契約、必讀文件、檔案所有權與交付仍依 `AGENTDECK.md`（ADR 0035），本指引不減免既有查找與驗收要求，也不是每次製作都要讀。

## 先確定這次改的是什麼

讀既有 `plan.md`、資料來源與 `edits.js` 的註解，在 plan 補記本次來源、版本／日期、受影響的頁面與待確認事項，不另造一套追蹤格式。

- **同定義的新數值**：確認欄位、單位、樣本範圍與計算方式相同，追查哪些呈現與文字使用了它。
- **定義或條件改變**：例如分母、評分方向、實驗方法或資料範圍不同，不能直接當作同條件比較；重新判斷圖表、說明與結論是否適用。
- **新增或刪除案例**：確認穩定 ID、排序與缺值語意，避免把新案例對到舊案例的人工修改或註記。

來源缺漏或定義不明時標為待確認，不把缺值填成零，也不把模擬或人工替代值寫成實測。

## 沿資料的使用位置更新

從主題持有的資料或既有生成器追到使用處，優先沿用已有計算與檢查。共用資料只在原本的來源更新；不要為一次換值建立新的資料框架，也不要全域替換碰巧相同的數字。

| 使用位置 | 要確認的連動 |
| --- | --- |
| 圖表與表格 | 數值、比例、單位、軸範圍、排序、最高／最低標記、圖例與來源 |
| 衍生結果 | 加總、平均、百分比的分母、並列與缺值處理；除零結果不可默認為零 |
| 頁面文字與講稿 | 標題、lead、point、detail、instruction，以及既有 explain 中的比較、結論與限制 |
| 靜態後備與素材 | previewArt、預先生成的圖像、回放資料；不能主畫面已更新而後備仍是舊值 |
| 相關入口與產物 | 共用資料的另一冊、附件、下載檔與已交付的 ZIP／匯出檔是否需要重建 |

例如 B 從75變95、超過原本最高的 C90，不只改長條長度：最高標記、標題與講稿中的「C最高」也要重判。比較不同批次時保持可比較的尺度；若數值超出既有尺度，調整呈現並交代變更，不把圖形截斷。

若已存在 speech、audio、cues 或 record，檢查文字與時間點是否仍對應。需要重建時依既有進階內容規則處理；尚未同步的音檔或動作要明確回報，不把它當成已更新的交付，也不順便替沒有語音的簡報新增語音。

## 保留人工修改與表達自由

不改寫或清空 `edits.js`。保留既有頁面 ID 與元件 key；排序改變時，依元件 API 使用明確 key，讓原有項目仍對到自己。人工註解按既有規則處理與回報，不自行刪除。

實際播放時檢查套用人工修改後的結果。如果人工覆寫使舊數值或結論繼續顯示，指出受影響頁與衝突，依使用者指示處理；不能只確認 story.js 正確就宣稱更新完成。

同定義換值時可沿用適合的元件；新資料若揭露了原版型無法表達的關係，重新選擇、修改下游副本或自製。維持舊版外觀不是比清楚表達更高的要求。

## 驗證與交付

先列出受影響位置，沿用既有檢查，核對來源與至少一組可獨立確認的預期結果；不要只比對生成器自己的輸出。依本次資料檢查適用的邊界，例如並列、缺值或新增案例，不為不存在的情境建立通用測試系統。

在實際閱讀器確認資料、尺度、結論與講稿一致，數字變長或項目增加後仍可讀；涉及互動時也確認切換、換頁返回、人工修改與靜態後備。共用資料影響多個入口時，各入口都要確認。這些重點用來安排檢查，不取代 `AGENTDECK.md` 的逐頁審查與打包後驗證。

交付時簡短說明資料從哪一版更新到哪一版、結論是否改變、驗證了哪些內容，以及未同步或待確認之處。區分資料核對、實際播放與離線交付的結果；未重建的舊匯出檔不算新版成果。
