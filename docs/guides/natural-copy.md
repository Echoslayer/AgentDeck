# 自然文案指引（建議）

適用於聽眾會看到或聽到的文字：`title`、`lead`、`point`、`detail`，以及進階的 `speech`。目的是讓文字像人為了這群聽眾寫的，而不是照規格填出來的。這是寫作建議，資料契約與標記仍依 `AGENTDECK.md`。

## 先寫聽眾看完要做到什麼

動筆前，在 `plan.md`「目的」寫成聽眾的行為，例如「願意看完、學會一件事、想回去試」，不寫「介紹某某」。目的未確定時，併入 `AGENTDECK.md`「先對齊需求與資源」那一輪詢問，不自行假設；人授權自行決定時記為假設。

章節與頁面標題寫「這段讓聽眾得到什麼」，不只寫主題名。標題寫不出來，表示這頁的主軸還沒定，先回去定主軸。

| 只寫主題名 | 寫出聽眾得到什麼 |
| --- | --- |
| 派工流程 | 第二次派工為什麼一次就過 |
| 事實查核 | 收稿後只比對引號句與數字 |

## 只用乾淨的必要素材寫文案

寫文案時只看原始素材，改版時再加上舊稿。內部規格表、元件文件、企劃表格與製作紀錄不放進寫稿的工作範圍，它們的用語會滲進文字。

- 自己寫：先依素材與目的把各頁文案寫完，再處理元件、標記與版面，不邊查規格邊寫句子。
- 交給 subagent 寫：只給原始素材、舊稿與一段任務說明（聽眾、看完要做到什麼、下方的事實底線）。不附 `AGENTDECK.md`、元件文件或整份 `plan.md`；把文案放進 `story.js` 由主 agent 做。

## 結構自由，硬限制只鎖事實

任務說明直接寫「整個結構重寫、自由發揮」，一次只要一版。不另外加字數、秒數、句數等規矩；`AGENTDECK.md` 既有的限制在放進頁面時再處理，不寫進寫稿的任務說明。

事實底線不能動：

- 數字、原話（引號內的句子）、事件與先後順序照素材，不改寫、不補。
- 素材裡的個人是否具名由人決定；未確定時併入需求對齊那一輪詢問，未獲同意前不具名。
- 素材沒有的結論不寫；需要時列進 `plan.md`「待確認」。

## 寫稿與查核分成兩步

寫的時候只寫，不同時自我審查。寫完後另做一次事實查核：

1. 逐一比對引號句與數字，對回素材的出處。
2. 只回報事實不符的地方，不改句子、不評文筆。
3. 由寫稿的一方依回報修正該處，其餘文字不動。

宿主支援 subagent 時，查核交給沒寫過這份的 subagent；不支援時，寫完全部文案後再回頭做，不逐句邊寫邊查。查核不取代 `AGENTDECK.md` 的逐頁邏輯審查。
