# 門檻與共識：實作追加說明

## 資料與固定條件

`series` 是 `{id, values}` 的陣列，ID 唯一，每組 values 等長且為 0–1 有限值。同一索引必須代表同一位置或項目。標籤由 demo.js 提供，不由計算函式推定。示範的數字是比較分數，不是機率或必須總和為 1 的占比。

## 狀態與計算

使用者改門檻、參與來源 ID 與 rule；原始 values 不變。`value >= threshold` 計一票；majority 為 `floor(N/2)+1`，all 為 N，any 為 1。N 為目前參與的來源數；零來源回傳 required=null、所有 pass=false。

一次更新依序計算票數與通過狀態，再同步更新原值表格的亮格、票數圖、規則標題與摘要。未參與來源仍顯示原值及門檻結果，但明確標示未投票。

## 改寫位置

- 在 demo.js 更換 labels、series 與控制項文案；欄位可代表區域、候選項或檢查項。示範圖的三欄排列只供六個位置使用，換欄位數時調整版面。
- 若來源值域不同，先在主題端定義轉換與單位；不可為了讓值域一致而偷偷正規化。改用非 0–1 範圍時同步修改驗證與控制項。
- 領域資料先映射為來源與對齊的 values；各數值的專業語意與解讀限制留在主題說明中。
- 嵌入 reader 時，改用 root 範圍的查詢，在 mount 綁定事件並回傳清理；state 按來源 ID 保存勾選，不按 DOM 排列順序保存。靜態預覽提供一組已計算結果。
- 共識只描述規則結果。分類是否正確、是否可信等領域結論留在主題；動態摘要只報可計算的數量。
- 本例標籤是受信任的作者常數；接外部文字時用 textContent 或跳脫後插入，並先驗證數值與 ID。

## 驗收

驗證等於門檻時入選、全部／至少一組／過半數、兩来源過半仍需兩票、無来源與非法 ID。再確認每個亮格可追溯到數值和票數、控制改變後沒有殘留舊狀態、換頁返回正常，文字換行不裁切圖。
