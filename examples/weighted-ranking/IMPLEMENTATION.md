# 加權評分：實作追加說明

## 資料與假設

`items` 為 `{id, scores}` 陣列，ID 唯一。各 scores 與 weights 等長，分數在 0–max、有限且愈高愈好；權重是有限非負數。示範採三項 0–10 人工分數，不對應任何實測產品或模型。

權重除以總和得到 normalized。各貢獻為 score × normalized，總分為貢獻加總。全零權重回傳 total=null，不應顯示 0 分或宣布贏家。相同總分保留來源順序，畫面以 1e-9 的絕對誤差容忍浮點計算並列；不要因輸入排列不同宣稱有優劣。

## 更新流程

滑桿／預設情境 → 正規化權重 → 各項貢獻 → 總分與排序 → 更新長條、百分比與領先項目。原始分項表格不變。長條尺度固定 0–max，圖例對應分項；各段長度為 contribution/max，不能各列自行填滿。

## 改寫位置

1. 改 demo.js 的 criteria、items、起始權重與 max。標籤、色彩與預設按鈕都屬於主題。compute.js 不含模型名稱或「某項一定第一」等結論。
2. 成本、延遲等愈低愈好的數值須先明確轉成愈高愈好的分數；說明轉換公式。不同單位先確定尺度可比，不能只調權重掩蓋單位差異。
3. 不保證排名一定翻轉：若 A 各項不低於 B，非負權重不會讓 B 超越 A。由實際輸出決定提示，不沿用範例方案的固定結論。
4. 嵌入 reader 時，將查詢限制在 root，mount 管理事件與清理；state 按 criterion ID 保存權重。靜態預覽使用指定起始權重的结果。
5. 本例文字是作者常數；接外部資料需驗證欄位與數值，文字以 textContent 或跳脫處理。

## 驗收

等權重、單項權重、全零、相同分數、支配關係與非法數值都要檢查。各段貢獻和需等於總分，權重總和需為 1（全零除外）；縮窄視窗時表格可捲動，長條仍保持共用尺度。
