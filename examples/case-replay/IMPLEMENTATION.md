# 同案例結果回放：實作追加說明

## 資料與固定條件

`cases` 為 `{ id, label, variants }` 的非空陣列。案例 ID 唯一，每個案例的 `variants` 含唯一的 `baseline`，結果 ID 在該案例內唯一。各結果保存 `{ id, label, values, timeMs }`。

`values` 是同一案例中等長、非空的 0–10 有限數值陣列，同一索引對應同一位置；`timeMs` 為非負有限毫秒。標籤與內容由作者維護。範例的數字全部為人工資料，位置值不是機率，也沒有真正執行效能量測。

更換實測資料時，案例、量測定義、單位、前處理、參照版本與條件的差異都由主題說明。不同尺度不要偷偷正規化後宣稱可直接比較；耗時不同時不要自行補出品質提升的結論。

`evidenceRefs` 是 `caseId/variantId` 紀錄識別，不是外部文件連結。改用影像、熱圖或 JSON 時，將 ID 對應到主題自己持有的本機檔案。播放不得依賴來源專案、網路或上游範例路徑。

## 狀態與更新

操作輸入是 `caseId`、`variantId`，原始資料不變。`replay` 選出該案例的基線與結果，計算 `result.timeMs - baseline.timeMs`。未知案例或結果直接報錯，不默默改用另一個案例或基線。

每次更新兩側位置值、耗時、結果標題、差值摘要、來源 ID 與結果包，必須使用同一次選取的結果。變更案例時，基線也跟著換成該案例的基線。實際資料若有案例缺少某結果，更新選單或明示無資料，不混用別的案例。

本例是預先結果回放：只選紀錄，瀏覽器計算差值。沒有推論服務或即時實驗。

## 嵌入與編輯範圍

- 改寫到 reader 時，用主題前綴 class 與 root 範圍的查詢，頂層元件加唯一 `data-key`。
- 在 `mount(root, state)` 保存案例與結果 ID，綁定事件並同步回傳清理函式。返回頁面保留選擇，`previewArt` 提供同一組靜態對照與來源說明。
- 初次掛載和後續更新只替換結果容器，不重建包含作者說明的整個元件。固定的可編輯說明放在結果容器外，保留已套用的 `edits.js`。
- 案例數值、來源 ID、差值與依資料產生的文字保持鎖定，不加 `data-edit`。同一頁的 `data-key` 不會隨 `caseId` 自動形成另一份人工修改。
- 若需要人寫案例註記，以主題的 `notes[caseId]` 管理內容與保存方式；不要共用一個頁面 key 承載不同案例的註記。本例不新增註記儲存器或編輯器。
- 接外部文字時，用 `textContent` 或跳脫再插入；本例 `innerHTML` 只插入驗證後的數字，標題及來源使用 `textContent`。

## 驗收

`node examples/check.cjs` 檢查同案例基線、切換結果、差值方向、未知 ID、重複 ID、缺基線與非法量測值；並以本例控制項更新畫面，確認參照、結果、來源 ID 與摘要不殘留上一個案例。

嵌入 reader 後還需實際播放：切 A → B → A，換頁返回、縮圖、窄版面與不同文字長度。另在編輯模式修改固定說明，再切換案例與結果、換頁返回，確認修改不被覆蓋，結果數字仍不可編輯。程式檢查不等同瀏覽器排版驗收。
