# evolution

## 用途
逐步加入能力的有向無環圖。讀者選階段，觀察保留了什麼、新增了什麼，以及新增的原因。零套件依賴；屬特殊元件，由核心管理互動生命週期。

## API
`deck.evolution(key, { nodes, edges, stages })`

- `nodes: [{ id, label, since, text? }]`：唯一英數／底線／連字號 id、純文字名稱、開始出現的階段索引（0 起算）、可選純文字產物說明。
- `edges: [{ from, to }]`：方向表示處理或依賴關係；端點須存在、不可重複或形成回圈。連線在兩端都出現後顯示。
- `stages: [{ title, reason? }]`：純文字階段名稱與演進原因；可以有不新增節點、只解釋差異的階段。
- HTML 依連線自動分層，文字換行決定方塊高度；SVG 只畫連線。窄容器改為直向。適合約 3–8 個節點的概念圖；複雜網路請拆成多頁。
- 階段保留到重新整理，以頁面 ID 與元件 key 區分。無需自行寫 `mount`／`previewArt`。縮圖與圖片匯出保留完整圖、每個節點的「接自」關係及所有階段原因。
- 節點 label/text、階段 title/reason 支援現場編輯；切階段不重建這些內容。節點 key 為 `<key>-<id>`；改版保留 id。
- 進階連動：根元素在初始化及選階段時發出冒泡事件 `deck:evolution`，`event.detail = { key, step }`。當前階段也在根元素的 `data-step`；頁面 mount 註冊事件，核心隨後啟動元件並送出初始階段，回傳移除監聽器的清理函式。

## 必須保留
- 階段表示能力逐步加入，不表示執行時間、日期、效能或真實部署。尚未加入的節點保留虛框；不要把虛框當成已存在能力。
- 原因必須說明前一版的具體缺口。節點間箭頭不代表因果已經驗證。
- 一份圖只使用一種連線語意，文字必須說清楚；不支援循環、節點刪除或換線。改造／替換另用前後比較頁。
- 靜態後備需可獨立閱讀；不要只在事件處理器中提供理解必需的資料。
- 前後版本的試做、預測與結果回放由主題維護；使用 `agentdeck docs project-growth --code` 看教學範例。
- 驗收文字不出框、連線不穿過節點、窄版不橫向裁切、換頁進度保留，以及現場編輯後切階段仍保留文字。

## 範例
```js
art: deck.evolution('project', {
  nodes: [
    { id: 'input', label: '接收資料', since: 0 },
    { id: 'save', label: '保存資料', since: 1, text: '重啟後仍能讀回' },
  ],
  edges: [{ from: 'input', to: 'save' }],
  stages: [
    { title: '記憶體版本', reason: '先讓輸入能進來。' },
    { title: '持久保存', reason: '前一版重啟就丟失資料，因此加上保存。' },
  ],
}),
```
