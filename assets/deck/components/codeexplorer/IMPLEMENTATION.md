# 資料與閱讀約束

## 作者的工作

1. 固定來源版本，把相關檔案摘錄成完整 `lines`；不要混用另一個 checkout 的行號。
2. 從使用者的問題追起：誰建立資料、誰呼叫、如何跨事件、誰接手／釋放。
3. 以「有意義的責任」建立節點，再填原始碼範圍；函式內的失敗分支可獨立成節點。
4. 每条 edge 寫出關係與證據。`A → B` 不能省略「直接呼叫」或「經事件分派」的差異。
5. 解說講理由與副作用，不逐字翻譯語法。區分已核對的程式行为與待確認的執行環境。

## 表示與生命週期

`deck.define` 產生單一根元素，資料以跳脫後的 JSON 留在元件內。`live` 掛載互動內容；離頁關閉 dialog、移除事件及動態 DOM。狀態依入口路徑、頁面、元件 key 與来源版本隔離，保留到重新整理。根元素固定提示可編輯，掛載不覆寫。

縮圖、匯出与未啟動時顯示起始節點：責任、第一段最多 12 行原碼、輸入／輸出、限制與閱讀路線。它不代表完整程式；另有片段時應回 HTML 探索。

Highlight.js 對整檔解析後再拆行，保留跨行註解狀態。折疊由遮罩過的高亮文字配對 `{}`；此為閱讀輔助，不是 AST 或正確性檢查。來源語言不存在或套件缺少時停用自動折疊，保留純文字。

放大採原生 modal dialog，移動既有代碼面板而非複製內容；Esc 及還原按鈕會把同一面板放回。切換節點時，行號、高亮、作者解說、關係與檔案版本一同更新。

## 筆記與版本

作者解說屬於簡報資料；讀者筆記是可選功能。`notesKey` 應跨簡報與資料集唯一。筆記包含 file、sha、line、text；瀏覽器保存可能受隱私模式與 file URL 規則影響，JSON 備份才可攜。清空一行後儲存即刪除該行筆記。匯入不會改寫來源、作者解說或人工 `edits.js`。

## 維護檢查

執行 `node assets/deck/components/codeexplorer/check.cjs`。檢查基本資料契約、範圍、跨行高亮、折疊、解說切換、放大返回與來源缺失後備。另以 CLI `add` 在獨立單位取副本、`pack` 後離線播放，避免只在上游展示頁正常。
